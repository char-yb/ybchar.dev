# Visual Playbook

## 목적

이 문서는 `ybchar.dev` 기술 글에서 이미지를 언제, 어떤 형태로 넣는 것이 자연스러운지 정리합니다.

## 대표 이미지

- 최근 기술 글은 대표 이미지를 자주 사용합니다
- 대표 이미지는 글의 주제를 한 번에 이해시키는 용도여야 합니다
- 없으면 생략해도 됩니다

## 고가치 시각자료

### sequence diagram

적합한 경우:
- 비동기 요청 흐름
- API -> queue -> worker -> DB 같은 경계 설명

### flowchart

적합한 경우:
- 상태 전이
- 분기와 실패 처리
- 복구 흐름

### comparison table

적합한 경우:
- 설계 대안 비교
- 기술 선택 이유 정리
- 장단점 및 트레이드오프 정리

### screenshot

적합한 경우:
- IDE, 콘솔, 대시보드, 서비스 UI 가 실제 teaching point 일 때

## 이미지 수량 가이드

- 글당 1~3개의 고가치 이미지면 충분합니다
- 각 문단마다 이미지를 붙이는 방식은 피합니다
- 텍스트만으로 충분하면 이미지 제안 없이 가도 됩니다

## Mermaid 규칙

- 노드 라벨은 독자 친화적인 한국어 의미를 우선합니다
- raw 명령명, 클래스명, 메서드명만 나열하지 않습니다
- 구현 세부는 코드 블록이나 본문에서 설명합니다

## 캡션 규칙

- 캡션은 `무엇을 보여주는지` 와 `왜 필요한지` 가 바로 보여야 합니다
- 예시:
  - `표 1. TSID, UUIDv7, AUTO_INCREMENT 비교`
  - `그림 2. Redis reserve 이후 비동기 발급 흐름`
