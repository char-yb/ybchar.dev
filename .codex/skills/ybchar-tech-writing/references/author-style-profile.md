# Author Style Profile

## 목적

이 문서는 `ybchar.dev` 기술 글에서 반복적으로 보이는 문체와 구조 신호를 정리합니다.

기준은 최근 기술 글 다섯 편입니다.

- `2025-01-01` Java 21, Spring boot 3.4.x 마이그레이션 과정
- `2025-03-02` LocalStack과 DynamoDB 사용기
- `2025-03-16` 소프트웨어 디자인도 전략적으로, 전략 패턴에 대해
- `2026-04-11` Lua 스크립트로 Redis 원자성 보장하기
- `2026-04-13` TSID는 왜 사용하는가

회고 글은 따뜻한 연결 표현만 약하게 참고합니다.

## 문장 톤

- 기본 종결은 `합니다`, `해보겠습니다`, `봤습니다` 계열입니다
- 딱딱한 설명문보다 친근한 실무 공유 톤이 자연스럽습니다
- 초반에는 `왜 이 글을 쓰는지`, `어떤 문제에서 출발했는지` 를 먼저 꺼냅니다
- 1인칭 실무 공유 문장을 허용합니다
  - `이번에 제가 부딪힌 문제는 ...`
  - `구현하면서 제가 중요하게 본 포인트는 ...`
- 다만 친근함이 정확성을 밀어내면 안 됩니다

## 구조 패턴

- `문제 제기 -> 개념/구조 -> 과정 -> 예상치 못한 이슈 -> 결론/후기` 흐름이 자주 보입니다
- 질문형 소제목을 자연스럽게 씁니다
  - `왜 이 글을 쓰게 되었는가`
  - `왜 Redis 기본 명령 조합만으로는 부족했을까`
- 필요할 때 비교표나 다이어그램을 넣습니다
- 설명이 부족한 대신 짧아지는 글보다, 독자가 이해할 만큼 풀어 쓰는 글이 맞습니다

## 제목 패턴

기술 글에서 강하게 반복되는 제목 패턴은 아래 세 가지입니다.

1. `기술명 + 사용기/과정`
2. `짧은 훅 + 주제 + 에 대해`
3. `왜 ... 인가`

예시:

- `LocalStack과 DynamoDB 사용기`
- `Java 21, Spring boot 3.4.x 마이그레이션 과정`
- `소프트웨어 디자인도 전략적으로, 전략 패턴에 대해`
- `TSID는 왜 사용하는가`

## 금지 신호

- 과한 마케팅 카피
- 비유만 남고 기술 설명이 빠진 문장
- `백엔드 개발자 관점에서` 같은 메타 프레이밍의 반복
- `한다체` 중심의 차가운 서술
- 억지로 웃기려는 장식 문장
